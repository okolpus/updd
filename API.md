# Semantic Atlas API contract

Base /api. Same-origin browser. Server: Go (`backend/`), one binary that also serves the embedded React build. Auth via HttpOnly cookie (JWT HS256 with server-side session revocation). All errors JSON {detail:string}. JSON field names below are authoritative. Create/upload stores the text and returns 201 with status "processing"; entities and links are computed in the background (two at a time) and the summary carries {status: processing|ready|error, progress 0–100, stage: extract|entities|relations|graph|report|done, note, error}. Notes, questions and exports answer 409 until status is "ready". Interrupted analyses resume on server start. Optional fields on create/upload: subgenre (e.g. Роман), depth (basic = up to 30 entities/80 edges, full = 70/220).

POST /auth/register {login,name,password} -> 201 {user}; POST /auth/login {login,password} -> {user}; POST /auth/demo {} -> {user,document_id}; POST /auth/logout -> {ok:true}. GET /auth/me -> user directly {id,login,name,language,private,avatar}. PATCH /profile {name,language,private,avatar} -> user. avatar is validated data:image PNG/JPEG/WebP (≤500 KB, ≤3000 px).

GET /documents?q=&sort=created|title|author -> array of summaries {id,title,author,year,genre,created_at,word_count,entity_count,edge_count,status}. POST /documents JSON {title,author,year:null,genre,content} -> 201 full document. POST /documents/upload multipart file,title?,author?,year?,genre? -> 201 full document; an empty title defaults to the file name without extension (used by drag-and-drop). GET /documents/{id} -> full. GET /documents/{id}/status -> summary only (for polling). POST /documents/{id}/analyze {depth?} -> 202 summary, restarts the analysis. PATCH /documents/{id} {title,author,year,genre} -> full. DELETE /documents/{id} -> {ok:true}.

Full document = summary plus {content,analysis:{method,limitations,entities:[{id,label,type:person|concept|place|event,count,description,quotes:[{text,chapter}],degree}],edges:[{id,source,target,type:family|social|thematic|causal|temporal|cooccurrence,label,weight,evidence:[string],inferred:true}],chapters:[{id,title,text,word_count,themes:[string],entity_counts:{entityId:number},event_count}],keywords:[{word,count}],word_count}}. Entity ids strings. Chapter field in quote is the chapter title. Graph entities max 70, edges max 220; all chapters included. Analytical method disclosed in UI. All edges are evidence-backed hypotheses; co-occurrence never claims kinship/causality.

GET /documents/{id}/notes -> array {id,entity_id:null,fragment:null,text,created_at}. POST same {text,entity_id:null,fragment:null} -> 201 note. DELETE /documents/{id}/notes/{note_id} -> {ok:true}.
GET /documents/{id}/questions -> array {id,question,answer,sources:[{text,chapter}],mode,created_at}. POST same {question} -> 201 question object. Extractive QA only (no generative model); cites actual source fragments.

GET /documents/{id}/export.pdf -> binary PDF (DejaVu Sans, Cyrillic); GET /documents/{id}/export.png -> binary PNG graph. GET /health -> {status:ok,database:ok}.

Demo is an isolated random account with an original Russian expedition short story in 5 chapters. Foreign IDs are 404 for all nested routes. Deleting a document removes its notes and questions. Passwords: PBKDF2-SHA256 (260000 rounds), format compatible with the earlier Python version. Session cookie SameSite=Lax; Secure via COOKIE_SECURE=true behind HTTPS. Mutating requests from a foreign Origin get 403; bodies over 16 MB get 413. SQLite locally, PostgreSQL via DATABASE_URL (postgres://…). Max file 12 MB; max text 500000 words / 12 million characters; EPUB decompression limits; scanned PDFs without a text layer are rejected with an OCR hint. No arbitrary file paths, no outbound calls.

Local language model (optional): GET /ai -> {enabled,available,model,url,models,reason}. Create/upload/analyze accept ai=true (multipart "1"); if the model is unavailable the request gets 422 with the reason. With ai, a stage "ai" (82%) runs before "report": the model (Ollama /api/chat, JSON mode, think=false) checks entity names/types, merges duplicates, drops noise and labels up to 40 strongest links (edges get description, by_ai; entities by_ai; analysis.ai = {model,entities,merged,removed,edges,error}). Questions use the model when available: mode "ai:<model>", answer cites [n] of the returned sources; on failure the extractive answer is returned. Evidence quotes always come from the source text.

Configuration (environment): OLLAMA_URL (default http://127.0.0.1:11434), OLLAMA_MODEL (default qwen3:4b), ATLAS_AI=off, ATLAS_ADDR (default 127.0.0.1:8765), DATA_DIR (default backend/data), DATABASE_URL, SECRET_KEY (otherwise generated into DATA_DIR/.jwt-key), COOKIE_SECURE, FRONTEND_ORIGIN (Vite dev origin), FRONTEND_DIR (serve UI from disk instead of the embedded build).
