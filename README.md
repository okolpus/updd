# Семантический атлас

Программа для исследования художественных и учебных текстов. Перетащите книгу в окно — приложение разберёт её на главы, найдёт персонажей, места и события, построит интерактивный граф связей «кто с кем связан», покажет цитаты, аналитику и темы глав. Можно сохранять заметки и искать фрагменты по вопросам.

Сервер написан на **Go**: это один исполняемый файл, в который встроен веб-интерфейс (React + Ant Design + D3).

## Быстрый запуск

Понадобится **Go 1.22 или новее** (на macOS: `brew install go`, либо установщик с https://go.dev/dl/). Если установлена более старая версия, Go сам скачает нужную при первой сборке. Готовый интерфейс лежит в `frontend/dist`, поэтому Node.js для обычного запуска не нужен.

На macOS дважды нажмите `start.command` или выполните в папке проекта:

```bash
bash start.sh
```

Первый запуск собирает сервер в `bin/atlas` (нужен интернет для загрузки Go-модулей), следующие запускаются сразу. Откройте **http://127.0.0.1:8765**. Остановка — Ctrl+C в терминале.

Данные хранятся в `backend/data`: SQLite-база и ключ подписи сессий. Не удаляйте эту папку. База совместима с предыдущей Python-версией: созданные в ней аккаунты, тексты, заметки и вопросы продолжают работать.

На первом экране создайте аккаунт или нажмите **«Открыть пример»** — отдельный демоаккаунт с оригинальным учебным рассказом.

## Интерфейс

Дизайн сделан по макетам Figma (Library Dashboard, Add Text Screen, Analysis Progress Screen):

- **Моя библиотека**: карточки текстов со статусом «Готово», «Анализируется» (с живым процентом) и «Ошибка», фильтры по автору, жанру, типу и дате, поиск в шапке.
- **Добавить текст**: сведения о тексте (название, автор, год, жанр, тип), выбор глубины анализа «Базовый» или «Подробный», зона загрузки файла и ручной ввод текста с автосохранением черновика.
- **Анализ текста**: пять реальных этапов анализа с процентом и заметкой о найденном, после завершения сразу открывается граф.
- **Текст**: граф связей, чтение по главам, аналитика, заметки и вопросы к тексту.

Анализ идёт в фоне на сервере: можно вернуться в библиотеку и добавлять другие книги, карточки обновятся сами.

## Как добавить книгу

- **Перетаскиванием.** Бросьте один или несколько файлов в любое место окна. Появится подсказка «Отпустите, чтобы проанализировать», затем карточка с прогрессом. Название берётся из имени файла, его можно поменять кнопкой с карандашом. После анализа сразу открывается граф.
- **Кнопкой «Выбрать файлы»** на стартовом экране (можно выбрать несколько).
- **«Добавить текст»** в библиотеке: вставить текст или загрузить файл с указанием автора, года и жанра.

Форматы: TXT (UTF-8 или Windows-1251), EPUB, PDF с текстовым слоем. До 12 МБ на файл, до 500 000 слов. Сканы без текстового слоя нужно сначала распознать (OCR).

## Что можно делать

- Регистрироваться, входить и выходить; менять имя, фотографию и настройку приватности профиля. Интерфейс на русском языке.
- Хранить несколько произведений с названием, автором, годом и жанром; искать, сортировать, редактировать и удалять.
- Исследовать граф: двигать узлы, масштабировать, фильтровать типы сущностей (персонажи, места, события, понятия), искать узлы и открывать подтверждающие цитаты связей.
- Читать текст по главам, смотреть частоту упоминаний, ключевые слова и динамику событий по главам.
- Добавлять заметки к произведению, сущности или выделенному фрагменту.
- Задавать вопросы и сохранять историю найденных фрагментов.
- Скачивать PDF-отчёт и PNG-граф.

## Как устроен анализ

Анализ выполняется на сервере локально, без внешних API и платных ключей. Формы слов сводятся к общей основе по окончаниям русского языка (Анна, Анне, Анной → одна сущность; фамилии на -ов/-ова не смешиваются с другими словами). Заглавные слова в середине предложения становятся кандидатами в имена; соседние имена образуют полные имена («Анна Морозова»). Слова после «в/из/на» и после слов-маркеров («река», «станция», «город») становятся местами («Река Обь», «Станция Полюс»). События ищутся по словарю («экспедиция», «буря», «находка»…), понятия — среди существительных, которые распознаются по предлогам и типичным суффиксам. Совместные упоминания в предложении дают связи; языковые маркеры («брат», «встретились», «поэтому», «после») уточняют их тип.

Каждую связь нужно проверять по цитатам: это эвристики без словаря и нейросети, имена могут разделяться или объединяться неверно. Система не подтверждает родство, причины или мотивы. Граф ограничен 70 сущностями и 220 связями; полный текст доступен в режиме чтения. Вопросы обрабатываются **поиском подходящих цитат**, без генеративной модели.

Документы всегда доступны только владельцу аккаунта; публичная публикация и совместный доступ не реализованы.

## Нейросеть Qwen (необязательно)

Если хочется, чтобы анализ уточняла нейросеть, можно поставить локально Qwen через Ollama. Всё работает на твоём компьютере, текст никуда не отправляется. Без Ollama приложение работает как раньше.

1. Установить Ollama: `brew install ollama` (или приложение с ollama.com) и запустить её: `ollama serve` или просто открыть приложение Ollama.
2. Скачать модель: `ollama pull qwen3:4b` (около 2,5 ГБ). Для 8 ГБ памяти подойдёт `qwen3:4b` или `qwen3:1.7b`, для 16 ГБ и больше — `qwen3:8b`.
3. Перезапустить атлас. Другая модель задаётся так: `OLLAMA_MODEL=qwen3:8b bash start.sh`.

После этого на экране «Добавить текст» включается переключатель **«Уточнить с помощью Qwen»**. Что делает модель:

- получает найденные сущности с цитатами: исправляет названия и типы, объединяет дубли («Анна» и «Анна Морозова»), убирает мусор, пишет короткое описание роли;
- получает 40 самых сильных связей с предложениями-доказательствами и подписывает их: «брат и сестра», «конфликт», «вместе ищут карту»;
- отвечает на вопросы к тексту 2–4 предложениями только по найденным цитатам, со ссылками [1], [2].

Всю книгу целиком модель не читает: на ноутбуке это заняло бы часы. Ей отдаются только найденное и доказательства, поэтому уточнение занимает от десятков секунд до нескольких минут. Если Ollama не отвечает, остаётся обычный локальный анализ, а в карточке и аналитике написано почему. В библиотеке у готового текста есть пункт меню «Уточнить с помощью Qwen».

Настройки: `OLLAMA_URL` (по умолчанию `http://127.0.0.1:11434`), `OLLAMA_MODEL` (по умолчанию `qwen3:4b`), `ATLAS_AI=off` — выключить совсем.

## Docker с PostgreSQL

Установите и запустите Docker Desktop. Создайте `.env` из примера и задайте независимые случайные значения:

```bash
cp .env.example .env
```

```bash
openssl rand -hex 32
```

Результат вставьте в `SECRET_KEY`, повторите команду для `POSTGRES_PASSWORD`. Затем:

```bash
docker compose up --build -d
```

Откройте http://127.0.0.1:8765. `docker compose down` останавливает контейнеры и сохраняет тома; `docker compose down -v` удаляет данные.

Для публикации на сервере настройте HTTPS на обратном прокси и `COOKIE_SECURE=true`. Локально на HTTP оставьте `COOKIE_SECURE=false`.

## Разработка

Структура:

- `backend/cmd/atlas` — точка входа сервера;
- `backend/internal/analysis` — анализ текста, граф, вопросы;
- `backend/internal/parsing` — чтение TXT/PDF/EPUB с ограничениями;
- `backend/internal/store` — SQLite/PostgreSQL;
- `backend/internal/export` — PDF-отчёт и PNG-граф;
- `backend/internal/server` — HTTP API, сессии, защита;
- `frontend` — интерфейс (React 18, Ant Design 6, D3, Vite); `frontend/embed.go` встраивает сборку в бинарник.

Тесты сервера и анализатора:

```bash
go test ./...
```

Интерфейс после правок нужно пересобрать, чтобы он попал в бинарник:

```bash
cd frontend && npm ci && npm run build && npm test
```

Для работы с Vite в отдельном терминале запустите `npm run dev` в `frontend`; `/api` проксируется на сервер. Проверка сервиса — `/api/health`.

Переменные окружения: `ATLAS_ADDR` (по умолчанию `127.0.0.1:8765`), `DATA_DIR`, `DATABASE_URL` (`sqlite:///путь` или `postgres://…`), `SECRET_KEY`, `COOKIE_SECURE`, `FRONTEND_ORIGIN`, `FRONTEND_DIR`. Полный контракт API — в `API.md`.

## Хранение и ограничения эксплуатации

Пароли хэшируются PBKDF2-SHA256 с отдельной солью; JWT хранится в HttpOnly-cookie, сессии записываются в базе и отзываются при выходе. Все операции с документами проверяют владельца. Файлы разбираются из памяти, EPUB не распаковывается на диск и ограничен по суммарному размеру. Изображения профиля проходят проверку формата и размеров. Запросы с чужого Origin отклоняются.

Анализ синхронный: во время загрузки интерфейс показывает ожидание. Для массовой многопользовательской нагрузки нужны фоновые задачи и очередь. Резервное копирование, отказоустойчивость и миграции схемы не реализованы.

Шрифт DejaVu Sans включён для кириллического PDF/PNG, лицензия — `backend/internal/export/assets/DejaVu-LICENSE.txt`. Лицензии компонентов — в `THIRD_PARTY_NOTICES.txt`. Деморассказ создан специально для программы.
